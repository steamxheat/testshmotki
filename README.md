# Шмотки — Telegram Mini App магазина одежды

Одна установка приложения — один магазин со своим владельцем, ботом и базой.
Для другого продавца разворачивается отдельная копия. Покупатель открывает витрину
по ссылке `https://t.me/<bot>/app?startapp=store_<slug>`. Владелец управляет
товарами, заказами, отзывами и настройками во встроенной админ-панели.

Для передачи отдельной копии продавцу используйте [актуальный чек-лист запуска](./docs/SELLER_LAUNCH.md).
Старые документы `DEPLOYMENT.md`, `HANDOFF.md` и `TRACEABILITY.md` описывают прежний вариант и не являются инструкцией для новой установки.

## Стек

| Слой | Технология |
|------|-----------|
| Клиент (Mini App) | React + Vite + TypeScript + Telegram WebApp SDK |
| Сервер / API | Node.js + Express + TypeScript |
| ORM / БД | Prisma + PostgreSQL |
| Бот и уведомления | grammY (Telegram Bot API) |
| Фоновые задачи | node-cron (снятие просроченной брони) |
| Хранение изображений | локальный диск (`/uploads`), абстракция под S3 |

Клиент, API и фоновые задачи живут в одном репозитории с чётким разделением модулей
(см. §13 ТЗ — микросервисы для MVP не нужны).

## Структура

```
server/   — API, бот, cron, Prisma-схема, сиды
web/      — Telegram Mini App (React)
docker-compose.yml — PostgreSQL для локальной разработки
```

## Быстрый старт

### 1. Поднять базу

```bash
docker compose up -d
```

PostgreSQL поднимется на `localhost:5434` (чтобы не конфликтовать с локальным 5432).

### 2. Сервер

```bash
cd server
cp .env.example .env         # при необходимости впишите BOT_TOKEN
npm install
npm run db:push              # создать таблицы
npm run db:seed              # создаёт магазин, владельца и категории; без демо-товаров
npm run dev                  # http://localhost:4000
```

### 3. Клиент

```bash
cd web
cp .env.example .env
npm install
npm run dev                  # http://localhost:5173
```

### 4. Открыть как Mini App

1. Создайте бота у @BotFather, получите `BOT_TOKEN`, впишите его в `server/.env`.
2. В @BotFather задайте Web App URL (для прод — HTTPS-адрес клиента; для локалки удобно
   прокинуть туннель, например `cloudflared tunnel --url http://localhost:5173`).
3. Ссылка на витрину: `https://t.me/<bot_username>/app?startapp=store_<STORE_SLUG>`.

Перед `db:seed` укажите в `server/.env` свой Telegram ID в
`STORE_OWNER_TELEGRAM_ID`, адрес магазина в `STORE_SLUG`, а при желании название и
контакт. В `web/.env` задайте тот же адрес в `VITE_DEFAULT_STORE`. В продакшене
собирайте web с `VITE_API_URL=` для запросов к API на том же домене. Если
приложение размещено не в корне домена, задайте путь при сборке, например
`VITE_BASE_PATH=/shmotki/ VITE_API_URL= npm run build`.

### Режим разработки без Telegram

Только сервер с `NODE_ENV=development`, `ALLOW_DEV_AUTH=1` и без `BOT_TOKEN` принимает заголовок `X-Dev-User` (base64 JSON с
`{id, first_name, username}`) вместо подписанного `initData`, а магазин можно
передать query-параметром `?store=<STORE_SLUG>`. Это позволяет открывать и
отлаживать клиент прямо в браузере. Такой сервер слушает только `127.0.0.1`; с реальным ботом и в проде обход отключён (§10 ТЗ).

## Что реализовано (MVP, §3 ТЗ)

- Telegram-авторизация с серверной проверкой подписи `initData` (§10).
- Отдельная установка для каждого продавца; владелец назначается при настройке.
- Каталог, карточка товара, галерея 1–10 фото.
- Динамические категории и фильтры — только из актуального ассортимента (§6.4).
- Поиск без учёта регистра по названию/бренду/категории/описанию, debounce (§6.3).
- Избранное, привязанное к Telegram-пользователю (§6.6).
- Заявка на покупку + атомарная бронь на 24 ч (§6.7, §9.1–9.2).
- История заказов и статусы (§6.8).
- Отзывы после завершённой сделки, ответ продавца, пересчёт рейтинга (§6.9).
- Админ-панель продавца: обзор, товары (CRUD/дубли/архив/массовые действия),
  категории, заказы, отзывы, настройки (§7).
- Telegram-уведомления покупателю и продавцу (§8).
- Cron снятия просроченной брони (§6.7, §9).
- Аналитические события (§16).

Подробное соответствие пунктам ТЗ — в [docs/TRACEABILITY.md](./docs/TRACEABILITY.md).
