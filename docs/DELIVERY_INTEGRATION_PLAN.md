# Автоматическая доставка: минимальные действия продавца

Цель: после технической интеграции владелец магазина открывает «Настройки → Доставка», заключает договор с выбранной службой, вводит свои доступы и один раз заполняет данные отправителя. Разработчик не должен просить его изучать методы API, выбирать доступные ПВЗ вручную или присылать ключи в мессенджере.

| Служба | Что вводит владелец | Что ещё необходимо |
| --- | --- | --- |
| СДЭК | Идентификатор аккаунта и секретный ключ | Подписанный договор, данные отправителя, вес и габариты посылок |
| Почта России | Токен приложения и ключ пользователя | Доступ к «Отправке», данные отправителя и точки сдачи, параметры посылок |
| Яндекс Доставка | Токен API | Бизнес-кабинет, склад/станция отгрузки и её ID, параметры посылок |

Официальные требования: [СДЭК](https://apidoc.cdek.ru/), [Почта России](https://otpravka.pochta.ru/specification), [Яндекс Доставка](https://yandex.ru/support/delivery-profile/ru/api/other-day/access). Названия разделов личных кабинетов и условия договоров следует перепроверять перед запуском каждого магазина.

## Что требуется сделать в приложении

1. Сделать отдельное подключение на каждый магазин и службу. Только владелец вводит, заменяет и удаляет ключи через защищённую форму. Секреты хранятся только на сервере в шифрованном виде с отдельным ключом шифрования; их нельзя возвращать API, класть в публичные `Store.settings`, логи или бэкапы без шифрования. Кнопка «Проверить доступ» выполняет реальный запрос к выбранному перевозчику и показывает причину ошибки без вывода секрета. Статус «Подключено» должен означать успешную проверку доступа, а не просто наличие строки.
2. Добавить профиль отправителя и дефолтные размеры упаковки; разрешить переопределять вес и габариты в товаре или заказе. Перед расчётом проверять обязательные данные. Не подставлять выдуманный тариф, срок или QR-код.
3. При оформлении заявки получать актуальные ПВЗ, доступные тарифы и цену от API конкретной службы. Для СДЭК текущий публичный справочник ПВЗ — только временный режим выбора пункта, не создание отправления.
4. Создавать отправление **после ручного согласования продавцом**. Использовать идемпотентный ключ по заказу, хранить внешний ID, документы, трек-номер и ошибки повторной попытки. Не создавать вторую платную отправку при повторном нажатии. Получать статусы через поддерживаемый механизм перевозчика и уведомлять покупателя.
5. Разделять оплату товара, компенсацию доставки покупателем продавцу и оплату услуг перевозчика по договору. Для СДЭК отправление через API оплачивается владельцем договора, чьи ключи использованы; покупатель не получает отдельную автоматическую оплату СДЭК от одной только интеграции. Способ сдачи, ярлык и возможность QR зависят от службы и выбранного сценария.

СДЭК: защищённая форма, проверка ключей, тариф и сумма до заявки, создание отправления после оплаты и автоматическая проверка результата с выдачей трек-номера реализованы. Следующий этап: точные габариты каждого заказа, ярлык/штрихкод и обновление статусов движения посылки. Почта России и Яндекс Доставка пока остаются ручными способами; их ключи нельзя вводить в форму СДЭК или отправлять в чат.
