# СДЭК в Mini App

Продавец включает СДЭК как способ получения. Он не ведёт список ПВЗ получателя. Покупатель выбирает город и ПВЗ СДЭК на карте, а заявка сохраняет код, адрес и код города этого пункта.

Без ключей полный список действующих ПВЗ загружается из открытого JSON-адреса старого API СДЭК `integration.cdek.ru`. В памяти сервера хранятся только нужные поля, список обновляется раз в сутки; поиск городов и выбор точек работают без отдельного картографического ключа. Код повторно проверяется на сервере при создании заявки. Если этот публичный адрес перестанет работать, останется ручной ввод ПВЗ. Статичный список не хранится: [документация СДЭК](https://apidoc.cdek.ru/) предупреждает, что он быстро устаревает. Если у продавца есть `CDEK_CLIENT_ID` и `CDEK_CLIENT_SECRET`, сервер автоматически использует официальный V2 API `/v2/location/suggest/cities` и `/v2/deliverypoints`. Ключи не отправляются в браузер.

Владелец магазина открывает «Настройки → СДЭК», выбирает тестовую или рабочую среду, вводит `client_id` и `client_secret`, город и ПВЗ сдачи, ФИО/телефон отправителя и типовые габариты упаковки. Сервер проверяет ключи у СДЭК и хранит секрет в шифрованном виде. Если `CARRIER_ENCRYPTION_KEY` не задан, ключ выводится из `BOT_TOKEN`: смена токена без предварительного переноса ключей потребует повторного подключения магазинов. Не храните ключи в описании магазина, чате или `.env` клиента.

При выборе ПВЗ покупатель видит актуальный тариф СДЭК по подключённому договору и общую сумму. Перед созданием заявки сервер пересчитывает цену и отклоняет оформление, если она изменилась. Продавец подтверждает заявку и проверяет поступление оплаты. В карточке заказа «Рассчитать СДЭК» повторно проверяет тариф; если он отличается от согласованного с покупателем, автоматическое оформление блокируется. «Создать накладную» требует второго подтверждения и защищён уникальным отправлением на заказ. Результат асинхронный: сервер проверяет ожидающие накладные раз в 5 минут; продавец может проверить вручную раньше. Трек-номер появляется только если СДЭК действительно создал накладную; в рабочей среде покупатель получает уведомление.

Тестовый API СДЭК проверен на полном цикле: выбор ПВЗ, тариф, создание тестовой накладной и получение трек-номера. Для боевой проверки нужны ключи конкретного продавца. В поле компании отправителя передаётся название магазина.

Ограничения: цена рассчитывается по типовой упаковке, реальное место нужно сверять; стоимость услуг СДЭК списывается по договору продавца, а покупатель переводит ему деньги отдельно. Ярлык, QR для сдачи и автоматическое отслеживание пути посылки пока не реализованы. При сетевом таймауте повторное создание заблокировано: для заказа типа «Доставка» поиск СДЭК по номеру интернет-магазина не работает, поэтому результат нужно выяснять через поддержку перевозчика, сообщив время запроса и внутренний ID заказа. Старые заказы, созданные до сохранения кода города, нужно оформлять вручную.
